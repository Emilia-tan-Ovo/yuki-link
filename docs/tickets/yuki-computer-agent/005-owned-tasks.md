# YCA-005 — 启动、观察和停止自有电脑任务

**What to build:** AI 助手通过 YCA 启动非交互命令或程序，取得可追踪任务标识，在运行中查看输出和状态，并主动停止自己启动的任务、确认实际终止结果。

**Blocked by:** YCA-001 — 真实 PowerShell 短脚本闭环与完整结果；沿用直接执行与输出/失败契约，补齐持续任务的交互能力。

**Status:** ready-for-agent — 票据范围与验收标准已审阅；实施仍遵守技术依赖及 ticket-design 建议，未授权批量实施，验收待执行。

**Spec:** [已审阅规范](../../specs/yuki-computer-agent.md)；User Stories 17～20、33；A2 电脑任务条款、兼容要求及进程追踪待验证事实；A2-AC6、AC7、AC8，别名见[索引](README.md)。

## 范围与明确不做

- 一票交付启动 → 返回任务标识 → 运行中输出/状态 → 主动停止 → 核对终态，不把这些步骤拆成各自不可用的内部模块票。
- 复用现有进程持有、启动/停止和状态处理经验；任务是 YCA 直接执行，不要求 Codex session，也不通过 Codex 模型。
- 对自然完成、失败、超时、停止请求、停止中及实际终止提供可观察结果；输出受限情况沿用明确截断/中断反馈，不因未知结果自动重启任务。
- 仅操作持有的自有任务。实际程序是否仍受追踪需要验证，尤其是派生子进程或脱离父进程的程序，不因拿到 PID 就宣称可以可靠管理。
- 保留 A1 短调用用法；不做 GUI/键鼠、用户输入交互终端、系统服务/自启、任意外部 PID 管理、新调度框架或进程隔离研究。不把电脑任务跨服务重启持续运行作为本票新增承诺。

## 验收标准

- [ ] A2-AC6：启动一个持续输出的非交互任务，先返回标识，在其运行时能够读取新输出和当前状态；任务超过原短查询时长仍可管理。
- [ ] 使用相同标识主动停止该任务，先看到准确的停止进度，最终以实际进程退出确认终态；停止不等于撤销已产生的文件副作用。
- [ ] A2-AC7：自然退出、执行失败、超时和停止失败有明确结果；停止失败时不释放为“已停止”假象，不丢掉已可取得的输出。
- [ ] 通过可控夹具验证停止只作用于 YCA 自有任务及受追踪子进程；无效任务标识和非自有目标不导致无关程序被结束。
- [ ] 工具连接重新建立后，在服务仍运行的条件下可通过原任务标识继续观察，不能为获取结果而重复启动；异常/未知结果不触发无条件重放。
- [ ] A2-AC8：ChatGPT 经现有连接执行启动、运行中查询和停止流程，无 Codex 模型调用；A1 短脚本与现有 Codex 会话停止功能仍通过相关回归。

## 可复现验收方式

1. 使用无敏感内容、持续输出递增标记的非交互夹具，在公开 MCP 入口启动；取得任务标识后多次查询，确认输出与状态来自同一任务。
2. 让任务持续超过旧短查询时长，再主动停止并独立检查实际进程结果。另覆盖自然退出、显式失败、超时/超限和可控停止失败。
3. 用测试持有的父/子进程及不属于目标任务的控制进程验证终止范围；仅停止测试自身创建的进程，不枚举后批量杀死真实用户进程。
4. 在既有进程/存储测试接缝中复现难以稳定构造的错误，不要求重启生产服务制造故障。经 ChatGPT 复现自有任务闭环，记录运行中输出和终态证据。

## 随交付更新的文档

更新任务启动、标识保存、输出读取、状态与停止用法，以及超时/截断、连接中断和实际支持的程序生命周期边界；区分停止请求与终止，不宣传未验证的跨重启或脱离进程追踪能力。

## ticket-design 建议

**建议先做。** 任务标识、输出读取契约、状态转移、进程所有权与停止确认直接影响可用性和副作用判断。需要在现有能力上明确最小生命周期及错误恢复方式，不扩大成通用调度平台。
