# YCA-004 — 通过 PowerShell 完成 Git 项目操作

**What to build:** 艾米莉亚能通过 YCA 查看项目状态、完整目标差异和历史，并按任务执行本地分支、暂存、提交，再核对项目与提交结果。

**Blocked by:** YCA-001 — 真实 PowerShell 短脚本闭环与完整结果；需要其执行普通 Git 命令并返回结果。

**Status:** ready-for-agent — 票据范围与验收标准已审阅；实施仍遵守技术依赖及 ticket-design 建议，未授权批量实施，验收待执行。

**Spec:** [已审阅规范](../../specs/yuki-computer-agent.md)；User Stories 15～16、33；A2 Git 条款及兼容要求；A2-AC5、AC8，别名见[索引](README.md)。

## 范围与明确不做

- 通过通用执行复用本机 Git，补上现有 status/单文件 diff 之外的项目处理场景。已存在的 Git 查询接口继续可用。
- 允许以测试和文档交付已由 A1 支持的能力；只有实际缺口需要代码改动，不为每个 Git 子命令建立专用包装。
- 外部写入、凭据使用与破坏性操作仍遵循具体任务授权；通用 Git 能力不代表自动授权 push。
- 不做远端 Issue、真实远端 push、Git 工作流编排、冲突解决 Agent、强制 worktree 或新的 Git 抽象层。

## 验收标准

- [ ] A2-AC5：在临时项目中查看状态和历史、查看完整目标差异；覆盖现有专用 diff 无法完整表达的代表场景，例如多文件及删除文件。
- [ ] 创建/切换本地分支、暂存并提交样本改动，随后读取分支、提交和状态确认预期结果；不触碰用户真实项目历史。
- [ ] 非 Git 目录或无效参数等代表错误返回真实退出状态及已捕获输出；失败后不猜测成功，不无条件重试写操作。
- [ ] 原有 git_status/git_diff 的已支持输入和只读查询行为通过回归；普通 Git 执行与专用查询的适用范围说明清楚。
- [ ] A2-AC8：ChatGPT 经 YCA 完成本地 Git 操作场景，不调用 Codex 模型，不以 B 完成或真实远端 push 为验收条件。

## 可复现验收方式

1. 准备独立临时 Git 项目和仅用于该项目的测试身份，不修改用户全局 Git 配置；构造文本新增、修改和删除等样本改动。
2. 经公开 MCP 的通用执行查看差异、创建分支、暂存并提交；用 Git 的实际分支/历史/状态输出和文件状态核对。
3. 运行代表失败及旧查询接口回归；经 ChatGPT 和既有连接复现本地项目操作。全部证据来自临时项目，不使用真实凭据或远端写入。

## 随交付更新的文档

补充普通 Git 项目操作和结果核对示例，区分专用 status/diff 与通用执行；明确本票已验收本地操作，外部写入仍按用户任务授权处理。

## ticket-design 建议

**不默认需要。** Git 和 A1 已提供执行能力，当前没有新增外部契约的必要。若实际环境或返回语义阻止验收，先判断最小修正是否足够，再决定是否需要局部设计。
