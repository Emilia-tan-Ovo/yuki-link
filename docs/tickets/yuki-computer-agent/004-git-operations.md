# YCA-004 — 通过 PowerShell 完成 Git 项目操作

**What to build:** AI 助手能通过 YCA 查看项目状态、完整目标差异和历史，并按任务执行本地分支、暂存、提交，再核对项目与提交结果。

**Blocked by:** YCA-001 — 真实 PowerShell 短脚本闭环与完整结果；需要其执行普通 Git 命令并返回结果。

**Status:** completed — 已按既定范围通过 ChatGPT → YCA 真实验收；现有执行能力满足本票，无生产代码改动。

**Spec:** [已审阅规范](../../specs/yuki-computer-agent.md)；User Stories 15～16、33；A2 Git 条款及兼容要求；A2-AC5、AC8，别名见[索引](README.md)。

## 范围与明确不做

- 通过通用执行复用本机 Git，补上现有 status/单文件 diff 之外的项目处理场景。已存在的 Git 查询接口继续可用。
- 允许以测试和文档交付已由 A1 支持的能力；只有实际缺口需要代码改动，不为每个 Git 子命令建立专用包装。
- 外部写入、凭据使用与破坏性操作仍遵循具体任务授权；通用 Git 能力不代表自动授权 push。
- 不做远端 Issue、真实远端 push、Git 工作流编排、冲突解决 Agent、强制 worktree 或新的 Git 抽象层。

## 验收标准

- [x] A2-AC5：在临时项目中查看状态和历史、查看完整目标差异；覆盖现有专用 diff 无法完整表达的代表场景，例如多文件及删除文件。
- [x] 创建/切换本地分支、暂存并提交样本改动，随后读取分支、提交和状态确认预期结果；不触碰用户真实项目历史。
- [x] 非 Git 目录或无效参数等代表错误返回真实退出状态及已捕获输出；失败后不猜测成功，不无条件重试写操作。
- [x] 原有 git_status/git_diff 的已支持输入和只读查询行为通过回归；普通 Git 执行与专用查询的适用范围说明清楚。
- [x] A2-AC8：ChatGPT 经 YCA 完成本地 Git 操作场景，不调用 Codex 模型，不以 B 完成或真实远端 push 为验收条件。

## 可复现验收方式

1. 准备独立临时 Git 项目和仅用于该项目的测试身份，不修改用户全局 Git 配置；构造文本新增、修改和删除等样本改动。
2. 经公开 MCP 的通用执行查看差异、创建分支、暂存并提交；用 Git 的实际分支/历史/状态输出和文件状态核对。
3. 运行代表失败及旧查询接口回归；经 ChatGPT 和既有连接复现本地项目操作。全部证据来自临时项目，不使用真实凭据或远端写入。

## 已验收用法与结果（2026-09-17）

本票无需新增 Git 抽象或生产接口。ChatGPT 通过现有 `powershell_execute` 在独立临时仓库复用本机 Git，使用仅限该仓库的测试身份完成状态、历史、完整差异、本地分支、暂存和提交，全程未调用 Codex 模型，也未配置远端或执行 push。

- 完整目标差异覆盖 3 个文件：删除 `delete.txt`、修改 `modify.txt`、新增 `新增 文件.txt`；可查看多文件及删除文件场景，不受专用单文件 diff 的表达范围限制。
- 创建并切换到 `yca004-acceptance`，暂存后提交 `test: exercise local git operations`；提交后工作树恢复 clean，分支、HEAD 和历史均可再次核对。
- 在真正脱离 Git 仓库的系统临时目录执行 `git status` 返回退出码 `128` 和 `fatal: not a git repository ...`，失败没有被猜测成成功或自动重放。
- 既有 `git_status` 仍能报告 `M modify.txt`；`git_diff` 使用绝对文件路径可返回该文件完整未暂存 hunk。兼容样本随后通过普通 Git 恢复，临时仓库再次 clean。

普通项目操作可按任务使用 `git status`、`git log`、`git diff`、`git switch -c`、`git add` 和 `git commit`；专用 `git_status` / `git_diff` 继续适合受限只读查询。远端 push、凭据使用和其他外部写入仍需当前任务的明确授权，本票不授予这些权限。
