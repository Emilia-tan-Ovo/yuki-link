## 依赖与实施顺序

技术阻塞边：YCA-001 → YCA-003、YCA-004、YCA-005；YCA-006 → YCA-007。

YCA-002 可以在已有专用文件接口上独立完成；YCA-006 可以在已有 Codex Bridge 上独立完成，因此不添加虚构的 A1/A2 技术依赖。YCA-007 依赖 YCA-006 提供可记录、可续聊继承的原生权限 session。

实施与交付仍遵守已确认顺序：**YCA-001 → A2 的 YCA-002～YCA-005 → B 的 YCA-006～YCA-007**。A2 内建议按编号推进，但四票之间没有额外强制阻塞。无技术阻塞不表示改变用户确认的阶段优先级，亦不表示本轮可以自动开始。

A1 完成即可使用，不等 A2 或 B。A2 每票单独验收，不把四票全完成作为其中任一成果可用的条件。A 的运行与验收不依赖 Codex 模型、B 的版本核验或正式 yuki-link Ticket 001。

## 所有票的共同交付约束

- 以公开 MCP 接口及真实文件/Git/任务结果验收，最终包含 ChatGPT 经既有连接的用户可见调用证据；本机测试和健康检查不替代该证据。A 阶段不调用 Codex 模型。
- 保留现有通信、认证、runtime、tunnel/key 和已支持工具用法；不自动重放未知结果，不把通用脚本称为只读或天然幂等。必要兼容回归纳入对应能力票。
- 只对当前票确有阻塞的事实开展调查。资源上限、工具字段等由对应票处理；遇到必须扩大范围的情况，报告 Spec 条款、事实、影响与最小替代方案，停止扩展并交回用户决定。
- 不引入 G0、强隔离、VM/WSL、批准平台、强制 worktree、app-server 迁移或新调度框架。不清理诊断文件，不处理正式 yuki-link 票据。
- 每票随成果更新实际用法、兼容行为及验收状态；已有说明只在相应交付生效后更新。测试产物不包含凭据和完整个人配置。
- ticket-design 建议是后续流程建议，本轮没有调用该 Skill；其中只解决已列出的接口与行为问题，不重开已确认产品需求。
