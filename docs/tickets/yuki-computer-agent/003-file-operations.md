# YCA-003 — 通过 PowerShell 管理普通文件和目录

**What to build:** AI 助手能通过 YCA 创建和查看目录，复制、移动、重命名及按要求删除普通文件和含文件的目录；PDF、Word、图片等二进制格式同样可管理。

**Blocked by:** YCA-001 — 真实 PowerShell 短脚本闭环与完整结果；复用其通用执行与结果契约。

**Status:** completed — 已按既定范围通过 ChatGPT → YCA 真实验收；现有执行能力满足本票，无生产代码改动。

**Spec:** [已审阅规范](../../specs/yuki-computer-agent.md)；User Stories 9、12～13、16、33；A2 文件管理条款；A2-AC1 的目录部分、AC2、AC3、AC8，别名见[索引](README.md)。

## 范围与明确不做

- 优先通过已交付的通用 PowerShell 完成普通文件与目录管理，并以真实验收、回归和操作说明形成可用成果。代码无缺口时允许不新增生产接口。
- 按任务目标处理复制、移动、重命名和删除；使用普通文本及二进制样本证明操作不受正文格式限制。保留已有专用文件工具行为，不用新通用用法偷偷改变旧接口。
- 不为各个文件子命令机械新增工具，不做 PDF/Word 正文提取、图片理解、专用文本读取重建、长任务或文件同步平台。

## 验收标准

- [x] A2-AC1：经公开 MCP 创建并查看带中文/空格名称的目录，目录状态与实际磁盘一致。
- [x] A2-AC2：在验收目录内对文件和含文件的目录完成复制、移动、重命名和明确要求的删除；核对源/目标存在性及预期内容。
- [x] A2-AC3：包含普通二进制样本，复制/移动/重命名前后字节数与哈希一致，不因 PDF/Word/图片等格式而拒绝文件管理。
- [x] 目标冲突、缺失源或系统拒绝等代表失败有可核对输出和退出结果，不无条件重试或宣称部分完成即全部成功。
- [x] 现有专用接口的不覆盖用法保持兼容；通用脚本的行为由明确任务与所用命令决定，文档不混淆两者。
- [x] A2-AC8：经 ChatGPT → YCA 复现文件/目录管理场景，全程不调用 Codex 模型；没有任何 B 阶段前置要求。

## 可复现验收方式

1. 在独立验收目录准备文本与无敏感内容二进制夹具、含夹具的子目录。通过 A1 通用执行完成各项操作，保存前后目录清单和文件哈希。
2. 对移动/重命名检查旧名消失及新名保留内容，对复制检查两份内容相等，对明确删除检查目标消失。递归操作前核实目标落在验收目录内。
3. 用受控冲突/缺失源案例检查失败反馈，避免测试覆盖或删除真实资料；补充公开 MCP 行为测试及可复用操作示例。
4. 经 ChatGPT 和原连接复现代表场景。如果 A1 已满足所有功能，交付新增验收与用法文档即可，无需包装额外工具。

## 随交付更新的文档

补充目录及普通文件操作示例、结果核对方法和冲突反馈；明确“可管理二进制文件”与“暂未提供正文解析”的区别，不写成禁止操作 PDF/Word/图片。

## 已验收用法与结果（2026-09-17）

本票无需新增生产接口。ChatGPT 通过现有 `powershell_execute` 在隔离验收目录完成目录创建/查看、文件及含文件目录的复制、移动、重命名和明确删除，全程未调用 Codex 模型。

- 中文及空格路径可正常创建和枚举；文本复制后 SHA-256 一致，目录递归复制、重命名和边界内明确删除均与磁盘状态一致。
- 使用 68 字节 PNG 二进制样本贯穿复制/移动/重命名，最终 SHA-256 `98884e721ec2f605f3788f2bc39a61de305ff4f4fcaf26b6f4eabeebcd6c0fb4` 与原始值一致。这里验证的是文件管理，不代表提供 PDF/Word/图片正文解析或视觉理解。
- 受控“目标已存在”和“缺失源”案例均返回非零退出码；既有目标未被覆盖，缺失源没有生成目标。未知结果不重放。
- 专用 `filesystem_list` / `filesystem_read` 继续可用；`filesystem_write` 创建新文件成功，对既有文件不提供当前 hash 的覆盖请求仍返回 `FILE_EXISTS`，原内容保持不变。

常用 PowerShell 组合为 `New-Item` / `Get-ChildItem` / `Copy-Item` / `Move-Item` / `Rename-Item` / `Remove-Item`。递归删除前应先把目标解析并核对在明确验收/任务目录内；二进制文件按普通字节文件管理，不按扩展名做特殊拒绝。
