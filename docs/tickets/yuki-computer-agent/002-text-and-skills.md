# YCA-002 — 文本与本机 Skills 读取及文件更新兼容

**What to build:** AI 助手通过 YCA 直接读取学习文本、Markdown、源码和本机 Skill 正文，并能创建、修改文本文件；专用文件接口继续提供可核对内容和更新冲突反馈。

**Blocked by:** None — 基于现有专用文件接口即可交付，不需要 A1 脚本接口；实施优先级仍位于 A1 之后的 A2。

**Status:** ready-for-agent — 票据范围与验收标准已审阅；实施仍遵守技术依赖及 ticket-design 建议，未授权批量实施，验收待执行。

**Spec:** [已审阅规范](../../specs/yuki-computer-agent.md)；User Stories 9～11、14、33；A2 文件读取条款、兼容要求；A2-AC1 的文本/Skills 部分、AC4、AC8，别名见[索引](README.md)。目录创建的完整场景由 YCA-003 交付。

## 范围与明确不做

- 解决现有路径规则整体屏蔽本机 Skills 文档等实际读取缺口，允许任务所需的普通学习资料与项目文件读取，不沿用“所有区外文件不可读”的产品门槛。
- 保留并完善专用文本读取、创建和更新入口，以及已有哈希冲突和不覆盖约定。必要时按实际资料大小完善读取体验，字段和分段形式留给本票设计。
- 以文件内容核对为成果，不仅修改允许路径列表。既有单文件移动等专用接口的已支持调用需保持兼容。
- 不做二进制正文解析、图片理解、目录与二进制文件管理全套操作、Git、长任务或 Codex Skill 编排；直接读取 Skill 不等于让 Codex 使用 Skill。

## 验收标准

- [ ] A2-AC1：经公开 MCP 创建、读取和修改文本、Markdown、源码样本，中文与换行内容可核对；读取至少一个本机实际 Skill 正文，路径规则不再将其整体拒绝。
- [ ] 用任务明确指定的普通资料位置覆盖现有默认工作目录外的读取场景，不以复制资料进项目作为唯一变通办法；不读取真实凭据作为样本。
- [ ] A2-AC4：读取内容及哈希后由独立写入改变文件，再用旧哈希更新，专用接口明确拒绝且保留最新内容；正常哈希更新成功。
- [ ] 现有创建冲突、文本更新和不覆盖移动等用法保持其已承诺语义；扩大可读范围不静默破坏既有调用。
- [ ] 对超过单次读取能力的资料有明确反馈；如本票提供分段读取，应可重组并核对原内容，不静默漏字或截断。
- [ ] A2-AC8：ChatGPT 经现有连接实际读取资料并完成一个样本文本更新，整个流程不调用 Codex 模型，不依赖 B。

## 可复现验收方式

1. 准备无敏感内容的文本/Markdown/源码样本及任务指定的资料目录；使用现有公开文件工具创建、读取、更新，核对字节或内容。
2. 选取一个本机实际 Skill 只读取正文，另用可控夹具覆盖路径规则与大小边界；不修改真实 Skill 文件或个人配置。
3. 使用临时文件复现“读后被别人改写”的哈希冲突，以及目标已存在时的不覆盖行为。通过公开 MCP 返回和实际磁盘内容双重确认。
4. 运行文件接口针对性回归；在 ChatGPT 端复现读取与更新。记录确切支持范围，不将正文读取写成 Skill 实际执行。

## 随交付更新的文档

更新文件工具的读取范围、正文格式、大小/分段行为、冲突结果和本机 Skills 读取示例，准确保留旧接口约定及后置解析能力的说明。

## ticket-design 建议

**建议先做。** 现有路径拒绝规则把普通文档与敏感配置位置混在一起，需定清用户可读场景和专用接口语义；读取大小的处理若涉及新外部契约也在本票解决。不引入自定义强隔离或批准平台，不重新询问已确认的文本优先范围。
