# Yuki Computer Agent：直接电脑操作与 Codex 协作

状态：已审阅，拆票已审阅；票据 ready-for-agent，未授权批量实施，未实现或验收新增能力。

日期：2026-09-15。

依据：本轮 pair-with-docs 的现状核对、用户对三个待确认问题的统一回复，以及已确认的 A1 → A2 → B 交付顺序。本规范取代旧 G0/G0-B 对本次需求的约束；旧条件授权不沿用。

## Problem Statement

用户希望 ChatGPT 中的AI 助手能够通过 Yuki Computer Agent（YCA）实际使用自己的电脑：执行命令、处理文件与项目、读取资料，并查看和停止自己启动的任务。目前直接电脑工具只覆盖固定 PowerShell 查询、受限文本文件操作及少量 Git 查询，尚不能完成正常的电脑操作闭环。

已有 Codex 协作路径可以管理模型、会话和运行，但执行器固定只读并忽略用户配置。它没有尊重用户通常使用 Full Access 的习惯，也没有完成所需本机 MCP/Plugins 的真实调用验收。

这两类问题分别解决。普通电脑操作不应先调用 Codex 模型；让AI 助手能用电脑本身就是独立价值，不要求把 YCA 建成另一个编程 Agent。

## Solution

### 已确认的两条能力

- **A：直接电脑操作。** AI 助手通过 YCA 直接使用 PowerShell、文件、Git 和自有任务操作；不调用 Codex 模型，也不等待 B 完成。
- **B：Codex 协作。** AI 助手通过 Bridge 与 Codex 中的协作助手协作，保留现有模型、session、run、历史和幂等能力，补齐原生权限与所需本机环境。

YCA 是 yuki-link 的独立前置开发工具。本规范不启动正式 yuki-link Ticket 001，不改变既有 Device、Capability、Service、Provider 的领域含义，也不要求先接入统一核心或 provider。

本文中，session 指 Bridge 管理的 Codex 会话，run 指其中一次消息运行；电脑任务指 YCA 直接启动并追踪的命令或程序，不要求为它创建 Codex session。

### 分阶段交付

| 阶段 | 用户获得的能力 | 独立可观察成果 |
| --- | --- | --- |
| A1 | 直接执行真实 PowerShell 命令和脚本，先支持短时非交互调用 | ChatGPT → YCA → PowerShell → 创建、修改、读取验收文件 → 返回核对结果，全程无 Codex 模型调用 |
| A2 | 补齐文件、Git、运行中输出、状态和主动停止体验 | 实际处理文本及二进制文件、操作临时 Git 项目、启动并停止 YCA 自有长任务 |
| B | 使用用户选择的 Codex 原生权限及所需环境 | 同一 session 内完成实际读写、命令执行、续聊、合适 Skill 的使用及 Context7 调用 |

A1 完成即可独立交付；A2 可以在后续拆票时拆为可独立验收的能力。B 不构成 A 的运行或交付前置条件。此处是交付阶段，不是已拆好的 Ticket。

## User Stories

1. 作为AI 助手，我希望直接通过 YCA 执行 PowerShell 命令，以便无需先请 Codex 模型代操作电脑。
2. 作为用户，我希望 Codex 模型不可用时仍能使用直接电脑能力，以便两条能力可以独立使用。
3. 作为AI 助手，我希望在明确工作目录中提交多行脚本，以便完成包含多个步骤的实际任务。
4. 作为用户，我希望中文、空格路径、单双引号和换行按原意传递，以便中文文件及学习项目可以正常操作。
5. 作为AI 助手，我希望创建、修改并读取验收文件，以便用实际内容确认操作结果。
6. 作为AI 助手，我希望取得 stdout、stderr 和退出状态，以便区分正常输出、诊断信息与执行结果。
7. 作为AI 助手，我希望非零退出仍保留已捕获输出，以便定位失败发生在哪一步。
8. 作为用户，我希望超时或输出超限有明确结果并尽可能保留部分输出，以便不会把中断误当成功或丢失全部线索。
9. 作为AI 助手，我希望查看和创建目录，以便组织资料和项目文件。
10. 作为AI 助手，我希望读取和修改文本、Markdown、源码，以便协助用户学习和处理项目。
11. 作为AI 助手，我希望读取本机 Skills 正文，以便了解可以使用的工作方法。
12. 作为AI 助手，我希望复制、移动、重命名和按要求删除普通文件及目录，以便完成日常整理工作。
13. 作为用户，我希望上述文件操作同样适用于 PDF、Word、图片等二进制文件，以便暂未提供正文解析不妨碍文件管理。
14. 作为用户，我希望已有文本更新冲突检测继续有效，以便专用文件接口不会悄悄覆盖别人刚修改的内容。
15. 作为AI 助手，我希望查看 Git 状态、差异和历史，并按任务操作分支、暂存与提交，以便正常处理项目。
16. 作为用户，我希望 Git 外部写入、删除等行为遵循具体任务授权，以便执行能力不会被解释成无关操作的许可。
17. 作为AI 助手，我希望启动命令或程序并取得可追踪标识，以便随后查看自己启动的任务。
18. 作为AI 助手，我希望在任务运行中查看输出和状态，以便长任务无需一直占着一次工具调用。
19. 作为AI 助手，我希望停止 YCA 为我启动的任务并确认终止结果，以便控制任务生命周期。
20. 作为用户，我希望停止失败时如实显示仍未停止，以便不会误以为任务已经结束。
21. 作为AI 助手，我希望继续选择模型和 reasoning，并创建、续聊既有管理方式下的 session，以便保留与协作助手协作的体验。
22. 作为用户，我希望新 session 未指定权限时采用本机 Codex 默认，以便既有 Full Access 选择受到尊重。
23. 作为用户，我希望创建 session 时能够显式选择 Codex 原生模式，以便按当前任务使用合适的执行能力。
24. 作为用户，我希望创建时记录并返回实际采用的模式、续聊继承该模式，以便知道会话真正采用什么设置。
25. 作为用户，我希望旧 session 不静默改变权限，以便历史会话行为不会因本机默认变化而升级。
26. 作为AI 助手，我希望在同一 session 内完成实际文件读写、命令执行和后续消息，以便确认协作不仅是文字通信。
27. 作为用户，我希望 Codex 自己发现并实际使用合适 Skill，以便沿用工程工作流而不让 Bridge 编排 Skills。
28. 作为用户，我希望 Context7 在 Bridge session 中完成真实调用，以便至少一个必需 MCP 得到实际验证。
29. 作为用户，我希望其他 MCP/Plugins 尊重现有启用状态及 CLI 支持情况，以便不会为了方便验收而被统一关闭。
30. 作为用户，我希望区分插件已安装、CLI 识别、session 加载和调用成功，以便了解实际可用程度。
31. 作为用户，我希望非必验插件的问题单独记录，以便不会阻塞 A 或其他已可用能力。
32. 作为AI 助手，我希望已有 send/output/status/stop、历史与请求幂等继续工作，以便连接重试或续聊不会破坏既有协作。
33. 作为用户，我希望复用现有通信、认证、runtime 和 tunnel/key，以便获得新能力时不必重建现有连接与历史。

## Implementation Decisions

### 已确认需求与行为约束

#### A1：命令执行与结果

- 接受实际 PowerShell 命令/脚本，不再只允许四种固定查询。普通操作直接执行，不调用 Codex 模型。
- 使用 PowerShell 7。工作目录和脚本文本清楚分离；中文、引号、换行及脚本自身的语法不得被额外一层命令行拼接改变。
- 正常结果包括 stdout、stderr 和真实退出状态。非零退出不得丢弃已捕获的任一输出流。
- 超时、输出超限、进程启动失败等执行层错误必须可辨认；尽可能返回已捕获输出，并说明中断或截断。没有可确认退出码时不得伪造成功退出码。
- 不以 stderr 是否为空代替真实退出状态；保留命令输出与执行结果之间的区别。具体 PowerShell 错误流和原生命令退出行为列入实现验证。
- 保留必要超时、输出限制和错误处理；具体数值不在本规范中扩大或写死。A1 可以同步等待短时非交互脚本，运行中查询和主动停止属于 A2。
- 验收目录是明确操作目标，不是强隔离边界。通用脚本的实际访问能力受运行账号和系统权限影响；YCA 不擅自提权，也不将任意脚本包装成只读或天然幂等的工具。

#### A2：文件、Git 与电脑任务

- 提供正常的查看、创建、修改、复制、移动、重命名和按要求删除文件/目录的能力。可以通过通用执行完成，无需为每个子命令单独提供工具。
- 正文读取优先保证文本、Markdown、源码与本机 Skills 文档。普通文件操作不按内容格式排除二进制文件；正文解析与文件管理分别验收。
- 调整会阻止上述场景的现有限制，不能继续因 Skills 所在配置目录的整体屏蔽而拒绝普通 Skill 文档，也不把所有区外文件默认不可读当成产品前置条件。
- Git 使用现成 Git 能力，支持项目查看及按任务进行本地处理；现有 status/diff 入口保留。外部写入、凭据使用等仍遵循用户任务授权和工程约定，不因通用执行存在而自动获准。
- 电脑任务具备可追踪标识、运行中输出、状态与停止能力。停止针对 YCA 持有的自有任务，不以调用方任意提供的 PID 或进程名批量终止其他程序。
- 区分请求停止、正在停止和实际终止；错误、超时及已产生的输出应可观察。停止不回滚已经发生的文件或其他副作用。

#### B：原生权限与本机环境

- 本机 Codex 配置决定新 session 的默认权限模式；本轮讨论时核对到的 Full Access 选择不能被 Bridge 固定降为只读。
- 创建新 session 可以显式选择本机 CLI 支持的 Codex 原生模式；未指定时解析并采用本机默认。
- 创建时记录并返回实际采用的模式。后续消息沿用该 session 的模式，不随之后的本机默认变化而悄悄改变。
- 旧 session 不静默改变权限。首版不建设历史权限迁移或会话内模式切换；需要不同模式时新建 session。缺少新权限字段的旧记录不得自动套用当前 Full Access 默认。
- 权限模式是执行能力设置，具体操作仍由用户任务决定。原生参数组合及与批准策略的关系需由 CLI 实际验证，不重写 Codex 权限系统，不新建批准转发平台。
- 继承所需本机配置和环境，不为高隔离或验收方便统一关闭用户已启用的 MCP/Plugins；同时不得通过“启用全部”覆盖用户主动关闭的项目。
- Skills 由 Codex 发现和使用；Bridge 传输请求、管理运行并返回结果，不解释或编排 Skill 流程。
- Context7 是最低必验 MCP 样本，不是插件白名单。其他插件的兼容问题分别记录，不要求全部通过才交付 B。
- 对依赖分别记录“已安装”“CLI 已识别”“在 Bridge session 中加载”“实际调用成功”；不能把清单存在或模型自述当成实际调用证据，也不承诺与桌面端完全等价。

### 兼容要求

- 保留现有通信入口、连接认证、runtime、tunnel/key 引用和历史。新增能力不要求重新建 tunnel/key、迁移服务或清空历史。
- 现有 PowerShell 固定查询、文件工具及 Git 查询的已支持用法继续可用。增强接口可以调整新能力的输入与结果，但不能因扩展脚本执行而让原查询调用失效。
- 已有专用文件更新的哈希冲突检查、明确不覆盖行为等仍有价值；保留其对现有调用的约定，不把它们误称为通用 PowerShell 的操作系统级保护。
- 保留模型/reasoning 选择、显式校验和续聊继承，不静默降级到别的模型。已有 session 标识、Codex thread 关联、run 标识和历史保持可查询、可续用。
- 保留 start/send 的异步接收、每个 session 单个 active run、output 游标、status/stop 及请求幂等。同一请求标识和相同输入重试返回原运行，修改输入仍报告冲突。
- 新增权限输入必须参与新请求的一致性判断；读取旧请求映射和旧 session 时维持既有重试行为，不把旧记录当作新的执行请求。
- 保留持久化失败、恢复中断状态和不自动重放未完成副作用的既有处理。错误和不确定结果不能触发无条件重新执行。
- 保留正常远程工具的错误处理和必要操作记录；不把 key、敏感环境或完整个人配置写进 Spec、测试产物及审计。现有运行日志与直接电脑操作审计的职责分别保留。

### 复用建议与留给实现的细节

以下是建议，不作为指定新架构的要求：

- 复用现有 MCP/HTTP 入口、直接电脑工具、子进程启动/停止、UTF-8 传输和错误处理能力。
- 保留有实际便利性的文件读取/更新和 Git 查询接口；目录操作、二进制文件管理及普通 Git 子命令优先复用通用执行。
- 电脑任务管理复用现有进程持有、状态与持久化经验；不要求把电脑任务包装成 Codex session，不预设新的通用调度框架。
- B 优先沿用现有 CLI 执行器、会话管理、存储与模型目录模块；无需为了本规范提前迁移 app-server。
- 具体工具名称、脚本承载方式、输出截断形式、分段读取接口、任务存储形式及合理资源上限，留到拆票或必要的实现设计。不得借这些细节增加新的产品门槛。

## Testing Decisions

### 测试边界与既有基础

主要验收边界采用现有公开 MCP 接口：用真实 MCP 客户端提交请求，观察工具返回、文件内容、Git 状态和任务进程的实际变化。该边界对应已确认的 ChatGPT → YCA 使用路径，在 Spec 审阅中一并核对；不新增测试专用服务或逐层模拟整套系统。

自动化回归复用已有真实 MCP HTTP 客户端、临时文件/Git 仓库、PowerShell 7、UTF-8 管道和自有进程树测试。已有 Codex fake executor、存储及错误注入测试继续用于状态、幂等、恢复和故障场景；只有公开边界难以稳定触发的边界情况才在这些既有接缝补充测试。

测试外部行为，不镜像函数内部实现。旧测试中的只读/固定查询假设不能无条件阻止已确认的新能力；调整受影响断言，同时保留仍适用的冲突检测、错误处理和兼容回归。

真实 ChatGPT 经现有连接调用是用户可见端到端验收。本机 MCP 测试、tunnel 进程存在或健康检查成功不能替代它。A 的测试不得启动 Codex 模型；B 的实际模型验收只覆盖必要代表流程，不重复穷举全部模型和 reasoning 组合。

### A1 可观察验收

- [ ] 在明确验收目录中，经 ChatGPT → 现有 YCA 连接 → PowerShell 创建中文文件、修改内容并读取核对；记录预期内容与实际结果，整个过程没有 Codex 模型调用。
- [ ] 经同一公开 MCP 边界验证中文内容、带空格和中文的路径、单双引号及多行脚本；不能仅用 Node 回显测试代替 PowerShell 实际执行。
- [ ] 成功脚本返回 stdout、stderr 和退出状态；先输出内容再显式非零退出的脚本仍返回已捕获的两路输出及正确退出码。
- [ ] 实际 PowerShell 错误及原生命令非零退出不会被错误标记成成功；保留可核对的错误与输出，明确所采用的退出语义。
- [ ] 先产生可辨认输出再超时或输出超限的脚本报告对应原因，尽可能保留已捕获输出，并说明截断/中断情况；自有执行进程的结束情况如实返回。
- [ ] Codex 不可用的自动化场景中，直接电脑能力仍正常工作；现有固定查询和其他已支持工具调用通过针对性回归。

### A2 可观察验收

- [ ] 创建并查看目录，创建、读取、修改文本/Markdown/源码；读取一个实际本机 Skill 正文，内容可核对。
- [ ] 在验收目录对普通文件和含文件的目录执行复制、移动、重命名和明确要求的删除；包含二进制样本，以字节数/哈希等证明复制移动未改变内容、目标存在与源路径变化符合操作。
- [ ] 文件操作不因 PDF/Word/图片格式而拒绝；本项不要求提取其正文或理解图片。
- [ ] 对现有文件更新制造内容冲突，专用更新接口明确拒绝；现有不覆盖调用的行为保持可验证。
- [ ] 在临时 Git 项目中查看状态、历史和完整目标差异，执行本地分支、暂存与提交等代表操作，再读取 Git 状态和提交结果确认；不需要向真实远端 push 才证明本地 Git 能力。
- [ ] 启动一个持续输出的非交互任务，取得标识，在运行中读取输出和状态；超过原短查询时长仍可管理，并能主动停止后确认终态。
- [ ] 验证停止只作用于自有任务；停止失败、任务自然退出及执行错误有明确状态，不把“已请求停止”当成“已终止”。
- [ ] 这些电脑操作在不调用 Codex 模型的条件下完成；B 尚未交付不影响验收。

### B 可观察验收

- [ ] 未指定权限创建新 session，记录并返回本机有效默认；在已选择 Full Access 的环境下，不被 Bridge 降成只读。再覆盖显式选择另一受支持原生模式的输入与生效结果。
- [ ] 在同一个 Full Access session 中完成实际文件读取、创建/修改和命令执行，再续聊确认结果与上下文；结合实际执行结果和 CLI 配置证据确认权限，不依赖模型自述。
- [ ] 后续消息继承 session 权限；本机默认变化不会使已创建 session 静默切换模式。此类回归使用可控测试配置，不要求更改用户全局配置。
- [ ] 旧 session、run、历史和请求幂等可读取与续用，旧 session 不静默升级；无需迁移旧会话即可创建具有不同模式的新会话。

## Out of Scope

### 本次不做

- 正式 yuki-link Ticket 001 及统一核心/provider 接入。
- G0/G0-B、自定义强隔离沙箱、ACL/root-deny 研究、VM/WSL 隔离、自建提权批准平台，以及修复 Codex 上游隔离机制。
- 把独立 worktree、app-server 迁移或新调度框架设为产品前提。
- 把一次 Full Access 选择解释为任意无关操作的授权，或自动提升 Windows 权限。
- Bridge 编排 Skills，或把普通电脑操作改为经 Codex 模型代执行。
- 历史 session 的权限迁移、会话内权限切换工程，强制所有插件都通过的统一验收，以及桌面端完全等价承诺。

### 后置能力，不构成首个闭环的阻塞

- PDF/Word 正文提取、图片理解等。后续优先复用现成组件，不提前建设文档解析框架；这些文件仍可在 A2 中正常管理。

- A2 的运行中查询、主动停止和长任务管理不塞进 A1；它们仍属于本规范的后续交付阶段。
